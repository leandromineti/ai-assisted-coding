# ADR-0056 — learning_loop regraded from presence to a mechanism enum

`decided: 2026-09-04` · `status: accepted`

## Decision

`learning_loop` (`harness_features:` operations group, `kind_link: memory`, also
set by convention on category-5/6 reports as the demand-side supply row) changes
`value_type` from `presence` to `closed-enum`:

> who writes and who commits the agent's autonomous memory/skills:
> `background` (an out-of-loop process — scheduler, fork, pipeline, event
> cascade, or hook-fed extractor — writes AND auto-applies) | `in-loop` (the
> main agent writes persistent memory during the session, auto-applied) |
> `proposed` (an autonomous path produces candidates; a human commits — nothing
> auto-applies)

`false` keeps its meaning: no autonomous write path at all. The auto-apply line
the old note called "the real discriminator" is now legible in the values:
`background`/`in-loop` auto-apply, `proposed` does not.

## The longest-tracked deferral in the registry

Issue #13 opened 2026-07-30 with the key itself (hermes + codex) and tracked the
enum through seven dated comments: ai-memory stub→source-verified (`background`,
server cron), memos (`background`, event cascade), mem0 (`background`,
hook-capture→extraction), warp's deep-dive refining `manual` into
**agent-proposed, human-committed** (an auto-write path built and removed), and
ADR-0012 reaffirming the deferral at value-scope counting. Issue #34's decision
(2026-09-04: the rule binds keys, not enum values) dissolved the block; the
key-level fact has been many-times instanced for weeks.

Census from the existing cells (no re-reads; comments carry the citations):

- `background` (7): hermes-agent (interval-gated review fork, ON by default),
  codex (two-phase startup pipeline, feature `memories` default OFF), qwen-code
  (extraction + "dream" consolidation agents, both DEFAULT-ON — the inversion of
  its parent), ai-memory (server-side scheduler, auto-approving, default-on with
  a provider), mem0 (Stop-hook capture → V3 extraction, no human in loop), memos
  (event cascade, real and golden-tested — mounted OFF by default,
  `lightweightMemory`), ecc (hook-observed sessions → background Haiku analysis
  → instinct files).
- `in-loop` (1): claude-code (agent-written `memory/` dir + MEMORY.md, written
  by the main agent during the session; observed, docs-route).
- `proposed` (2): warp (server-suggested rules, accept chips,
  `is_autogenerated` deprecated — the auto path removed), gemini-cli (the
  "confucius" extractor lands patches in an `.inbox` nothing auto-applies —
  its own cell already reads "same verified-✗ shape as Warp's").
- `false` (4): dsh, aider, pi, cognee (agent-invoked tools, no loop in-repo).
- Unset (3): opencode, cline, continue — honest dots, unchanged.

Like ADR-0053's `sandbox`/`none`, the regrade's sharpest gain is on the ✗ side:
warp and gemini-cli had autonomous write machinery that a bare ✗ rendered
identical to pi's nothing. `proposed` is a two-instance value; `in-loop` stands
single-instance under key-scope.

## Argued and not admitted (with triggers)

- **Sub-typing `background` by trigger** (interval fork · startup pipeline ·
  server cron · event cascade · hook-fed extraction — five verified shapes,
  parked in the issue since 2026-08-18 as "venue vs trigger"). Not admitted: no
  recorded finding yet turns on trigger shape, and five one-instance sub-values
  would fragment the column the day it lands. Trigger: a finding that
  discriminates by trigger (e.g. a failure mode specific to event-cascade
  loops), or a second instance of any single shape becoming the story.
- **A default-on/off axis.** Half the finding here exactly as it was for
  `context_compaction` (codex and memos are `background` shipped off; qwen-code
  is on and auto-applying — "also a default-on token bill"), and the same
  answer: per-mechanism, carried by every cell comment, awaiting ADR-0050-style
  grammar pressure from a second key.
- **`manual` as a value.** The issue's original fourth label. Dropped: warp's
  deep-dive showed the store's Manual source is the *human* path beside a
  removed auto path — that is `proposed`, and a store with only human writes is
  `false` for this key's question.

## Consequences

- Registry entry regraded (value_type, definition, note rewritten to the census;
  `applies_to` stays `[2]` — category-5/6 reports keep setting the key by the
  existing kind_link convention, same enum).
- 13 set cells re-valued: 6 `true` → `background`, 1 → `in-loop`, plus
  ai-memory/mem0/memos/ecc → `background`; warp and gemini-cli `false` →
  `proposed` with lead-in rewrites; dsh/aider/pi/cognee stay `false`.
- `tools/_template-tool-report.md`'s learning_loop line updated to the enum.
- `tools/2-harnesses/README.md` presence recount (ten presence-claims, seven
  not — also folding in ADR-0055's two enums, missed in that commit's recount);
  `tools/5-memory/README.md`'s issue-#13 open-question bullet resolved, dated.
- Issue #13 closes: this ADR is the promotion it tracked; its other tracked
  enum (`plan_mode`) landed the same day as ADR-0054.
- Decoder: in prose written before 2026-09-04, `learning_loop: true` reads as
  `background | in-loop`; `false` as `proposed | false` — and the 4✓/4✗ balance
  the old note cited is now 4/2/2/... per the census above.
