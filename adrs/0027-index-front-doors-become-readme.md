# ADR-0027 — Directory front doors are named `README.md`, not `index.md`

`decided: 2026-08-26` · status: **accepted**

## Decision

The seven hand-kept front doors rename `index.md` → `README.md`, unchanged in content:
`docs/index.md` and the six `tools/N-*/index.md` category indexes.

`refs/index.md` **keeps its name** and is the rule's other half: it is generated by
`build-refs-index.py` and sits beside a hand-written `refs/README.md`. That pairing is
the convention this ADR makes explicit:

- **`README.md`** — the hand-kept front door: what this directory is, and what is in it.
- **`index.md`** — a *generated* listing over the directory's items, owned by a script.

## Why

Owner request (2026-08-26): GitHub renders `README.md` automatically when a visitor
opens a directory and renders nothing for `index.md`, so the repo's most-browsed
directories — the six category folders — opened onto a bare file list. The convention
above was already the de-facto practice everywhere else (`adrs/`, `articles/`, `refs/`,
`upstream/`, `experiments/*/` all use `README.md`); the seven renamed files were the
inconsistency, and `docs/index.md` was the clearest case — prose describing a directory,
which is a README's job, not an index's.

The counter-argument on the record, and why it lost: the `tools/N-*/` front doors
genuinely *are* indexes as well as front doors (narrative plus seed inventory), so
`index.md` was not simply wrong for them the way it was for `docs/`. It loses because a
file can only have one name and only one of the two names renders — and because the
generated/hand-kept split is the distinction the repo actually enforces (methodology
rule 3), which `refs/` now demonstrates in a single directory.

Two lint skips keyed on the old name and moved with it — `check_feature_registry` in
`scripts/check-taxonomy.py` and `collect()` in `scripts/build-tool-index.py`, both of
which exclude non-report files from the `tools/` tree. Both are scoped to `tools/`, so
`docs/README.md` was never in their path; the change is `path.name == "index.md"` →
`"README.md"` in each.

## The decoder

Anything dated **on or before 2026-08-26** cites these front doors as `index.md`:
`docs/index.md` → `docs/README.md`, and `tools/N-<name>/index.md` →
`tools/N-<name>/README.md`. `refs/index.md` is unaffected and means what it always
meant. Chains with the ADR-0024/0025/0026 decoders for material predating them.

## Boundary

Same as 0024–0026: living docs, `adrs/README.md`, `scripts/`, `known_sites`, and the
generated matrices are rewritten or regenerated; **ADR bodies and preregistered
experiment protocols keep their period paths** and read under the decoder above. No
link went stale under this rename — the front doors' old names survive only in ADR prose
and backticked mentions.

The `known_sites` finding from ADR-0026 repeated and is now a pattern worth stating: the
two entries this rename touched were re-derived rather than repathed, and **both were
line-stale as well** (`…/4-workflow-frameworks:118` → `:119`,
`…/5-memory:92` → `:84`). Four of the repo's `known_sites` entries have been re-derived
in one day and all four were wrong. They key on `file:line`, nothing verifies them, and a
stale entry silently vouches for nothing — so the whole list should be treated as
unverified until a check derives it, which is a candidate for the next lint change
(`known_sites` entries whose line no longer contains their compound are findings, not
silence).
