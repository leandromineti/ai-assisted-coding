# Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

`retrieved: 2026-08-18` · `read_depth: full` · [vendor research page](https://mem0.ai/research) · authors are the mem0 company (research@mem0.ai)

## What it does

Describes and evaluates mem0's two architectures on LoCoMo: **Mem0**, an
extraction/update pipeline (per message pair: summary + last-m messages → LLM extracts
candidate facts; an LLM "tool call" then picks ADD / UPDATE / DELETE / NOOP against the
top-s similar stored memories), and **Mem0^g**, which adds an entity–relation graph in
Neo4j with an LLM conflict detector and update resolver that *invalidates* rather than
deletes edges, preserving temporal reasoning (§2). All LLM operations are gpt-4o-mini.
Compared against six baseline classes: prior LoCoMo-evaluated systems, LangMem, RAG at
7 chunk sizes × k∈{1,2}, full-context, OpenAI's ChatGPT memory, and Zep (§3.3).

## Design

- **Dataset as actually used** (§3.1): LoCoMo = **10** conversations, ~26K tokens and
  ~200 questions each — and the **adversarial category is excluded** ("ground truth
  answers were unavailable"). So the released instrument is smaller than the LoCoMo
  paper's stated 50 conversations, and the category where the LoCoMo authors measured
  long-context hallucination collapse (2.1 F1) is not part of any mem0 number.
- **Metrics** (§3.2): F1 and BLEU-1 kept for comparability, but the paper argues they
  mis-score factual errors and leans on **LLM-as-a-Judge (J)** — 10 runs per method,
  mean ± sd. This confirms the metric-mismatch flag in
  [2024-locomo](2024-locomo.md): vendor J numbers live on a different scale from the
  LoCoMo paper's F1.
- Latency measured as search and total p50/p95; token footprint of each memory store
  measured directly (§4.4–4.5).

## Numbers worth keeping

- **Overall J on LoCoMo (Table 2): Mem0 66.88, Mem0^g 68.44 — full-context 72.90.**
  The no-memory baseline wins on quality; the paper says so plainly ("trailing only
  the computationally prohibitive full-context approach", §4.4).
- The trade actually claimed: Mem0 p95 total latency **1.44s vs 17.12s** full-context
  (a 92% reduction; search p95 0.200s), memory store **7K tokens** (Mem0) / 14K
  (Mem0^g) per conversation vs 26K raw context (§4.3–4.5).
- Per-category J (Table 1): single-hop 67.13 (Mem0), multi-hop 51.15 (Mem0),
  open-domain 76.60 (**Zep wins** this category), temporal 58.13 (Mem0^g). Graph
  memory helps temporal, is neutral-to-negative on single/multi-hop.
- Rival forensics: **Zep's graph store consumes >600K tokens per 26K-token
  conversation** — 20× the raw conversation — and its async graph construction made
  immediate recall fail, improving hours later (§4.5). LangMem search p50 is 17.99s.
- Best RAG configuration peaks at J≈61 — both mem0 variants beat all RAG configs by
  ~10–12% relative (§4.3).

## What it means for this repo

Resolves the grading question the instrument catalog opened, in three steps:
(1) the README's "LoCoMo 92.5" is not in this paper — the paper's best overall J is
68.44, so the marketing number belongs to a later (2026) eval that must be reconciled
separately if it ever matters; (2) the paper's *own* comparison shows the memory
system **losing to no-memory full-context on quality** — the honest claim is an
efficiency frontier (near-competitive J at ~8% of the latency and a fraction of the
tokens), which is a real but different claim than "best memory"; (3) the evaluated
instrument is LoCoMo-minus-adversarial at 10 conversations — the abstention-shaped
ability every memory system in BEAM's data handled *best* is exactly what mem0's
numbers never test. For the kind comparison: mem0's extraction/update pipeline is the
purest "LLM in the write path" design in the set (contrast ai-memory's zero-LLM
default), and its ADD/UPDATE/DELETE/NOOP tool-call is a one-shot, in-line counterpart
to ai-memory's scheduled auto-improve approvals — same decision, different venue and
cadence. Also updates [2024-locomo](2024-locomo.md): the public LoCoMo is 10
conversations, not the paper's 50.

## Limits

- Vendor paper about the vendor's product, arXiv-only (checked 2026-08-18:
  no peer-reviewed venue found), judge details in an appendix not read here.
- Single benchmark (LoCoMo), single inference model (gpt-4o-mini), adversarial
  category dropped; no significance testing beyond judge-run sd.
- Zep and OpenAI baselines are configured by mem0 (the Zep token/latency forensics
  are adversarial testimony until independently reproduced — same grading rule as
  ai-memory's issues-cognee dossier).
- The efficiency framing depends on full-context growing with conversation length;
  at LoCoMo's 26K tokens, full-context is still feasible and *better* — the paper's
  own Table 2 makes the "production-ready" claim a bet on longer conversations than
  its benchmark contains.
