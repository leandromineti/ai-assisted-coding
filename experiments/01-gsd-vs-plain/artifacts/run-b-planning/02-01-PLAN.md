## Interface contract (write these exact names)

Additions and changes to `gitwho.py`. Everything Phase 1 defined keeps its name and
signature except `fetch_log`, which gains one optional keyword argument.

- `fetch_log(path: str, since: str | None = None) -> bytes` — unchanged behaviour when
  `since` is `None`; the default keeps every existing call site valid.
- `sorted_stats(stats: dict[tuple[str, str], AuthorStats]) -> list[AuthorStats]` — new,
  pure, returns `sorted(stats.values(), key=lambda s: (-s.commits, s.name))`. Both
  renderers call it; neither sorts on its own any more.
- `render_json(stats: dict[tuple[str, str], AuthorStats]) -> str` — new, pure, returns
  the JSON document without a trailing newline (`print` adds it).
- `build_arg_parser()` gains `--since` (`metavar="DATE"`, `default=None`) and `--json`
  (`action="store_true"`). The `--json` flag lands on `args.json`; that is an attribute
  of the argparse namespace and does not shadow the imported `json` module — do not
  rebind the module name to it.

## Table and JSON contracts (the verification gates encode these)

The table contract is unchanged from Phase 1: header line, separator line of `-` runs,
one line per author; columns `AUTHOR`, `COMMITS`, `ADDED`, `DELETED`, `FIRST`, `LAST`
joined by exactly two spaces, every line right-stripped. Because author names contain
spaces but numbers and dates never do, gates address the numeric columns from the right:
on a data row `awk` field `NF-4` is COMMITS, `NF-3` ADDED, `NF-2` DELETED, `NF-1` FIRST,
`NF` LAST. Data rows begin at line 3. With an empty result set the header and separator
still print and there are zero data rows.

The JSON contract is P2-02: an array, two-space indented, one object per author, keys in
the fixed order `name`, `email`, `commits`, `added`, `deleted`, `first_commit`,
`last_commit`. With an empty result set the whole document is `[]`.

| 2 | name ending in ` Bad` (leading `Andr` + U+FFFD) | bad@example.com | 1 | 0 | 0 | 2024-01-07 | 2024-01-07 |

**Window `--since=2024-01-04T00:00:00+0000` — 3 rows, 4 commits total:**

| # | name | commits | added | deleted | first_commit | last_commit |
|---|------|---------|-------|---------|--------------|-------------|
| 0 | `Bob Brown` | 2 | 1 | 0 | 2024-01-05 | 2024-01-06 |

P-04, not a mistake; assert it exactly.

**Window `--since=2099-01-01T00:00:00+0000`** — zero commits: table prints header plus
separator and zero data rows, JSON prints `[]`, exit code 0.

`render_json(stats) -> str` — pure; the JSON document, no trailing newline.

**Changed signature**

`fetch_log(path: str, since: str | None = None) -> bytes` — the optional keyword keeps every
existing call site valid.

**CLI surface (complete, v1 final)**

`gitwho [path] [--since DATE] [--json]` — `path` defaults to `.` (CLI-01), `--since` is
handed to git verbatim (CLI-02), `--json` switches the renderer (CLI-03).

**JSON contract**

A top-level array, two-space indented, one object per author, ordered by
`(-commits, name)`. Keys in fixed order: `name`, `email`, `commits`, `added`, `deleted`,
`first_commit`, `last_commit`. Dates are `YYYY-MM-DD` UTC strings or `null`. Non-ASCII is
escaped as `\uXXXX`. An empty result set is `[]`.

**Exit codes (unchanged contract)**

`0` success — including a valid repository whose `--since` window selects nothing.
`1` empty repository or an unexpected git failure. `2` not a git repository.

**Test entry point**

`python3 -m unittest discover -s tests -v`, run from the repository root. Do not add
`-t .` — measured to fail without `tests/__init__.py` (P2-05).
