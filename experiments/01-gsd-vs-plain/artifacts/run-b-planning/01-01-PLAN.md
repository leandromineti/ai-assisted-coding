## Interface contract (write these exact names)

Subsequent tasks and all of Phase 2 build against these identifiers. Define them in
`gitwho.py` in this order.

Module constants: `RS = "\x1e"`, `US = "\x1f"`,
`LOG_FORMAT = f"{RS}%H{US}%an{US}%ae{US}%at"`.

Exceptions: `GitError(Exception)`, `NotARepoError(GitError)`, `EmptyRepoError(GitError)`.

Dataclasses:
- `FileStat` — frozen; fields `added: int`, `deleted: int`, `path: str`, `binary: bool`.
- `Commit` — frozen; fields `sha: str`, `name: str`, `email: str`, `epoch: int`,
  `files: tuple[FileStat, ...]`.
- `AuthorStats` — mutable; fields `name: str`, `email: str`, `commits: int = 0`,
  `added: int = 0`, `deleted: int = 0`, `first_epoch: int | None = None`,
  `last_epoch: int | None = None`.

Functions:
- `_run_git(path: str, *args: str) -> subprocess.CompletedProcess` — the only place in
  the program that spawns a process.
- `validate_repo(path: str) -> None` — raises `NotARepoError` or `EmptyRepoError`.
- `fetch_log(path: str) -> bytes` — raises `GitError` on a non-zero git exit.
- `parse_log(raw: bytes) -> Iterator[Commit]` — pure.
- `aggregate(commits: Iterable[Commit]) -> dict[tuple[str, str], AuthorStats]` — pure.
- `format_epoch(epoch: int) -> str` — pure, returns `YYYY-MM-DD` in UTC.
- `render_table(stats: dict[tuple[str, str], AuthorStats]) -> str` — pure.
- `build_arg_parser() -> argparse.ArgumentParser`.
- `main(argv: list[str] | None = None) -> int`.

## Table format (fixed — the verification gates grep it)

Header line, then a separator line of `-` runs, then one line per author. Columns in
order: `AUTHOR` (left-aligned), `COMMITS`, `ADDED`, `DELETED` (all right-aligned),
`FIRST`, `LAST` (dates, left-aligned). Columns are joined by exactly two spaces. Each
column's width is the longer of its header label and its widest value. Every emitted
line is right-stripped, so no line carries trailing whitespace. The header therefore
matches `^AUTHOR +COMMITS +ADDED +DELETED +FIRST +LAST$` and data rows begin at line 3.

Because author names contain spaces but numbers and dates never do, verification gates
address the numeric columns from the right: on any data row `awk` field `NF-4` is
COMMITS, `NF-3` is ADDED, `NF-2` is DELETED, `NF-1` is FIRST, `NF` is LAST.

Module docstring: state what the tool does, the usage line `gitwho [path]`, and the
merge-commit policy required by DATA-04, phrased as the sentence "Merge commits count as
one commit for their author and contribute no line stats." Task 3 appends the exit-code

`_run_git(path, *args)` is the single subprocess choke point. It calls `subprocess.run`
with the argv list `["git", "-C", path, *args]`, `capture_output=True`, and byte-mode
capture — pass no `text=`/`encoding=` argument at all, so stdout and stderr come back as
`bytes` (DATA-05: strict decoding by subprocess is what crashes on a non-UTF-8 author
name). Never enable shell interpretation; argv is always a list. Pass
`env={**os.environ, "LC_ALL": "C"}` so git's own message locale cannot vary the output
between machines.

`fetch_log(path)` makes the one and only `git log` call of the program, via `_run_git`,
with the arguments `log`, `--no-renames`, `--numstat`, and `f"--format={LOG_FORMAT}"`.
`--no-renames` is mandatory (DATA-03): it pins the numstat line to exactly three
tab-separated fields no matter what `diff.renames` the invoking user has configured. On
a non-zero return code raise `GitError` carrying the git stderr decoded with
`errors="replace"`. On success return `stdout` unchanged as `bytes`.

`parse_log(raw)` is pure and does the only decoding in the program:
`raw.decode("utf-8", errors="replace")` (DATA-05 — replacement, never strict). Split the
decoded text on `RS` into records, skip records that are blank after stripping, and for
each record partition on the first newline: the head splits on `US` into
`sha, name, email, epoch_text`; the tail is zero or more numstat lines. Note that git
emits a blank line between the header and the first numstat line, so the tail must skip
blank lines rather than assume its first line is data. Build one
`FileStat` per non-blank numstat line by splitting on tab with `maxsplit=2`; when the
added field is the single character `-` the file is binary, so set `binary=True` and
both counts to 0, otherwise `int()` them (DATA-02 — the guard runs before any `int()`
call, never after). Yield exactly one `Commit` per record, with `files` as a tuple that
may legitimately be empty — a merge commit produces a header with no numstat lines at
all (DATA-04), and that is the normal case, not an error.

`aggregate(commits)` is pure and folds into a `dict` keyed on the `(name, email)` tuple
(P-02), using `collections.defaultdict` or an explicit `setdefault`. For each `Commit`
increment `commits` by exactly 1 — counting happens once per `Commit`, never inside the
`files` loop, which is what makes a zero-file merge commit still count (DATA-04). Inside
the `files` loop add `added` and `deleted`; binary entries contribute 0 because
`parse_log` already zeroed them. Track `first_epoch`/`last_epoch` as a running min/max of
the commit's `epoch` integer, treating `None` as unset.

`format_epoch(epoch)` returns
`datetime.datetime.fromtimestamp(epoch, datetime.timezone.utc).strftime("%Y-%m-%d")`
(P-03). Epoch integers are compared; only the display string is ever formatted.

`render_table(stats)` sorts `stats.values()` with the key `(-s.commits, s.name)` (P-04,
CLI-04), displays `s.name` alone in the AUTHOR column (P-02), and emits the header,
separator and rows per the Table format section above, right-stripping every line and
joining with newlines.

`build_arg_parser()` returns an `argparse.ArgumentParser` with `prog="gitwho"` and a
single positional `path` with `nargs="?"` and `default="."` (CLI-01), helped as "path to
a git repository (default: current directory)".

`main(argv=None)` parses arguments, then runs `fetch_log` -> `parse_log` -> `aggregate`
-> `render_table`, prints the table to stdout and returns 0. Pre-flight validation and
the error exit codes are Task 3's job; leave the single call site for `validate_repo`
clearly placed as the first statement after argument parsing. Guard the entry point with
`if __name__ == "__main__": sys.exit(main())`.

Implement `validate_repo(path)` as two sequential, independently-branched `_run_git`
calls. First `rev-parse --is-inside-work-tree`; if its return code is non-zero, raise
`NotARepoError(path)` and do not run the second check. Only if the first succeeded, run
`rev-parse --verify HEAD`; if that return code is non-zero, raise `EmptyRepoError(path)`.

Both git invocations fail with the identical git exit code 128, empirically confirmed in
research — so the branch MUST be on which of the two checks failed, never on the numeric
code, and never on matching text in git's stderr (CLI-05 requires a pre-flight check
rather than stderr string-matching, because that text drifts with locale and git
version).

Wire `validate_repo(args.path)` in as the first statement after argument parsing in
`main`, inside a `try` that maps the exception type to the process exit code: catch
`NotARepoError` and return 2 (CLI-05), catch `EmptyRepoError` and return 1 (CLI-06). In
both handlers print gitwho's own plain-language message to `sys.stderr` — the not-a-repo
message contains the phrase `is not a git repository` and the empty-repo message contains
the phrase `has no commits`, each naming the offending path — and print nothing at all to
stdout. Do not echo git's raw stderr in either handler (threat T-01-03: raw diagnostics
leak internal detail and are not written for this tool's users); surfacing raw git text
is reserved for an unexpected `GitError` from `fetch_log`, which `main` catches
separately and returns 1 for.

A path that does not exist at all lands correctly in the `NotARepoError` branch with no
special-casing, because the first check is judged by its return code alone — research
verified git returns 128 for a nonexistent `-C` target too. Verify that sub-case
explicitly rather than testing only the "existing directory that is not a repo" variant.

Append the exit-code contract to the module docstring as the line "Exit codes: 0 success,
1 empty repository, 2 not a git repository." (P-01). PROJECT.md declares exit codes part
of the CLI contract, and Phase 2's README documents them from here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell argv -> gitwho process | The repo path is an untrusted user-supplied string that is forwarded to a subprocess |
| git subprocess stdout -> parser | Repository history is attacker-influenceable data: author names, paths and byte sequences in commit objects are arbitrary bytes |
| gitwho -> user terminal | Error output crosses back to the user and must not carry internal diagnostics verbatim |

| T-01-01 | Tampering | `_run_git` argv construction | medium | mitigate | argv is always a `list[str]` passed to `subprocess.run`; shell interpretation is never enabled and command strings are never interpolated. Gated in Task 1 acceptance criteria by a negative grep over non-comment lines (ASVS V5) |
